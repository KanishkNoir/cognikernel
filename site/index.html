Project memory for Claude Code & Codex

Your coding agent has
amnesia a memory.

Every session starts from zero: it re-reads the same files, re-derives the same architecture, re-asks what you settled last week. CogniKernel gives the project a memory that outlives any one session, so the agent stops paying the same cost twice.

$pip install "cognikernel[embedding]"

01 The problem

      
Amnesia by design

      
The model's weights are frozen, so its only memory is the context window. When a session ends, everything it learned about your project goes with it. Step through three sessions on the same question.

Context rot
A long session's window fills with stale tool output and superseded instructions until quality degrades.

      
Cold starts
The moment a session ends, its understanding is gone. The next one pays the "getting up to speed" cost again.

      
Repeat mistakes
The approach you abandoned on Tuesday comes back on Thursday, because nothing recorded why it failed.

    

  







  

    

      
02 How it works

      
One loop: observe, remember, recall

      
One side of the ring captures, the other recalls, and the event-sourced store at the centre holds it all. Click a stage, or let it cycle.

    


    

      

        
      

      

    

  







  

    

      
03 Four hook surfaces

      
It shows up at the moment it matters

      
CogniKernel attaches to a Claude Code session at four points, from the first prompt to the last turn. You never call it by hand.

    


    

      

        

        

          
SessionStart

          
Session block

          
Injects the canonical block of decisions, constraints, dead ends and an AST skeleton of the codebase.

          advisory
          
Why you care: no "let me re-read the codebase to remember where we were."

        

      

      

        

        

          
UserPromptSubmit

          
CK-1 recall

          
Surfaces memory relevant to what you just typed. Dual-evidence gated, and deduplicated against what's already in context.

          advisory
          
Why you care: ask about a subsystem and the prior decision rides in with your prompt, unasked.

        

      

      

        

        

          
PreToolUse

          
Read/Edit gate

          
Refuses re-reading a file already read this session. On Write/Edit, surfaces a past "don't do X" just in time.

          just-in-time strict opt-in
          
Why you care: the warning lands as it's about to break a past decision, not three files later.

        

      

      

        

        

          
Stop

          
Capture

          
Extracts and persists what this session decided, tried and ruled out, through the deterministic pipeline.

          side-effect
          
Why you care: you never hand-write memory into CLAUDE.md again.

        

      

    


    

      
      
Every surface fails open. If memory is unavailable or errors, the hook logs at WARNING, returns cleanly, and your session continues. Silence never reads as success: cognikernel doctor names any degraded subsystem.

    

  







  

    

      
04 What gets remembered

      
Typed memory, not text chunks

      
Every claim has a type, and the type drives how it's ranked, rendered and replaced. A dead end is stored differently from a decision because the agent should treat it differently.

    


    

      
DECISION
A choice that was made.
"use Redis for the rate limiter"

      
CONSTRAINT_HARD
A rule that must not be broken. Always kept when the block is trimmed to fit.
"never log webhook payloads in full"

      
CONSTRAINT_SOFT
A preference or convention, graded by how strongly it was stated.
"prefer dataclasses over dicts"

      
APPROACH_ABANDONED
A dead end, kept in the graveyard so it isn't re-attempted.
"in-process cache → counts drift"

    


    

      

        
Latest wins. The store fixes itself.

        
Each claim gets a decision key. When a later session restates or reverses a decision with the same key, the new claim supersedes the old one instead of piling up beside it. Recall returns one coherent answer, not a pile of revisions.

        
A fine-tuned cross-encoder catches the paraphrased cases a lexical key would miss ("swap the LRU for Redis" vs. "use Redis for rate limits"). And the old claim isn't lost: cognikernel why shows what replaced what, and show --as-of rewinds to what memory believed at any date or commit.

05 The injected block

      
What the agent sees at session start

      
A compact, budgeted Markdown block. Constraints are never dropped to make room, and ordering is deterministic so the prompt cache keeps hitting. Hover a note to find its section.

    


    

      

        
SessionStart · additionalContext

        

      

      

        
headerWhere you are
Project, session number and a state version, so the agent knows how much history sits behind this block.

        
hardNever violate
Hard constraints survive every budget cut. (×3) means three sessions stated the same rule and it was consolidated into one golden record.

        
threadActive thread
The open work item, carried over with its origin: (S3 · 09-12) means session 3, September 12.

        
skeletonWhere to look
The hottest files, backed by an AST skeleton of classes, methods and imports, so orientation costs fewer reads.

        
graveyardDo not retry
Abandoned approaches with the reason they failed, so the agent doesn't burn a session rediscovering it.

        
decisionsKey decisions
Ranked by authority, recency and centrality, each tagged with the session that made it.

06 The fine-tuned models

      
Classification, not generation

      
Most memory tools ship your transcript to another LLM and ask it to "summarize what mattered." CogniKernel treats extraction as a classification problem, so two small encoders run on your CPU in milliseconds.

    


    

      

        
salience_v2

        
decides what gets remembered

        
For every sentence in the transcript: is this worth keeping, and what type is it? A fine-tuned SetFit classifier on a bge-small backbone, exported to ONNX.

supersession_xenc

        
decides what gets replaced

        
Does this new fact replace a stored one (a decision changed, a constraint was relaxed), or is it a different decision in the same area? It reads both claims jointly and scores the probability that one supersedes the other.

Validated on held-out data, not vibes

        
Each model is scored against a frozen evaluation set mined from real project stores that training never sees. Because "is this a decision?" is genuinely ambiguous at the margin, the bar is how well two independent human labelers agree with each other, not a naive 100%.

      

      

        
Optional, on by default, fail-open

        
init configures the fine-tuned path; install-heads fetches the ~270 MB of sha256-verified weights. Skip it and CogniKernel still works on a deterministic lexical fallback, and doctor tells you which path is active.

Where it doesn't win

      
    
        
  • Small, re-readable projects. On Taskflow and Toolbelt, auto-memory scored higher on cross-session recall. When a project is cheap to re-read, structured memory adds little.
    • 
        
  • Against no memory at all, it's not always cheaper. On Relay, the project where it beats auto-memory by the widest margin, CogniKernel cost 23% more than the no-memory arm, from the round trips its own tools add.
    • 
        
  • Where it repays its overhead: projects that pile up several evolving decisions and several abandoned approaches. Relay had three supersession chains and three graveyard entries, and it's the only project where CogniKernel leads on every dimension.

08 Retrieval

        
Lexical first, dense as a signal

        
Never pure vector search. Exact terms matter in code, so BM25 leads and embeddings vote.

        

          
Hybrid coreSQLite FTS5 BM25 ∪ optional dense embeddings, fused with Reciprocal Rank Fusion.

          
prohibition_searchA type-restricted pool so a "do not do X" rule can't be crowded out by similar-sounding prose.

          
Skeleton graphAn AST symbol graph ranked by PageRank. find_related unions semantic neighbours with import-graph neighbours.

          
Golden records at readLatest-wins reconciliation at query time, so recall returns one answer per key.

        

      

      

        
09 Reliability

        
Degrades legibly, never silently

        
A memory layer that fails quietly is worse than none. Every failure path is tested and visible.

        

          
Atomic migrationsEach numbered migration applies its body and version bump in one transaction. Safe to crash mid-script.

          
Idempotent replayA re-run worker job can't double-count evidence or drift decay.

          
doctor --strictPer-subsystem health (schema, FTS5, embeddings, symbols, worker queue) with a non-zero exit when degraded.

          
Enforced architectureimport-linter layer contracts, guarded by a meta-test so a typo can't silently switch them off.

          
CI promotion gateLint plus the full suite, including failure-injection tests, on Ubuntu (3.11, 3.12) and Windows.

11 Quickstart

      
Three commands. Then just work.

      
Python 3.11 or newer. Run the setup once per project, from its root.

    


    

      

        

          
Install

          
The [embedding] extra adds dense retrieval and the runtime for the fine-tuned encoders. Recommended.

          

            
            
            
            
          

          

        

        

          
Set up the project

          
Registers the project and installs hooks and MCP for Claude Code and Codex.

          
$ cognikernel init .

          
$ cognikernel install-heads # ~270 MB, one-time, sha256-verified

        

        

          
Verify

          
Confirms every subsystem is wired up and names the fix for anything that isn't.

          
$ cognikernel doctor .

13 FAQ

      
Questions, answered

    

    

      

        Does any of my code or conversation leave my machine?
        
No project code or conversation is uploaded. Extraction, consolidation, storage, retrieval and model inference run locally against a SQLite database. With the recommended [embedding] extra, CogniKernel may download the local embedding model during initialization, and install-heads can download the fine-tuned weights; both paths fail open to lexical operation when unavailable.

      

      

        Is this another LLM summarizing my transcripts?
        
No. It's a deterministic sanitize → classify → consolidate pipeline. Two small fine-tuned encoders (~130 MB ONNX each, milliseconds on CPU) score salience and detect supersession. The only LLM involved is the coding agent you already run.

      

      

        Is it a vector database wrapper?
        
No. Retrieval is lexical-first (SQLite FTS5 BM25) with optional dense embeddings fused in via Reciprocal Rank Fusion. Memory is stored as typed events with provenance, not as loose text chunks.

      

      

        What happens if I skip install-heads?
        
Everything still works on a deterministic keyword/lexical fallback. It's weaker: it can miss decisions phrased outside its trigger vocabulary and paraphrased corrections. cognikernel doctor tells you which path is active.

      

      

        Which agents and platforms are supported?
        
Claude Code gets the full loop: session block, per-prompt recall, PreToolUse guardrails and capture on Stop. Codex gets the shared block and MCP recall, with capture pulled by codex-sync. CI runs on Ubuntu (Python 3.11 and 3.12) and Windows; WSL paths resolve to the same store as their Windows equivalents.

      

      

        Will it slow my sessions down or block my edits?
        
Hooks are fail-open and advisory by default. New projects start with the advisory read gate, which only refuses re-reading a file already read in the same session. Strict mode, which also refuses first reads of files in the skeleton, is opt-in via hook_policy = "strict".

      

      

        How do I see what it remembered, or why?
        
cognikernel show prints the store. cognikernel why <#id or words> explains where a claim came from, why it ranks where it does, and what it replaced. show --as-of <date|commit> shows what memory believed at that point. cognikernel reset clears it.

      

      

        What does "updates are paused" mean for me?
        
Development is on hold until further notice. v0.1.3 is the current release and stays current. It's stable, tested in CI, and Apache-2.0 licensed, so you can use it, fork it, or build on it.
